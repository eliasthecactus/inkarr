Anatomy of a plugin

A plugin is a folder with a package.json that has an inkarr key:

plugins/my-plugin/
├── package.json
├── server/index.ts     ← optional: indexers, clients, connections, tasks, routes
└── web/index.tsx       ← optional: pages, nav entries, book panels
{
  "name": "@me/inkarr-plugin-my-plugin",
  "version": "1.0.0",
  "type": "module",
  "description": "Shown on System → Plugins",
  "inkarr": {
    "id": "my-plugin",
    "server": "./server/index.ts",
    "web": "./web/index.tsx"
  },
  "dependencies": { "@inkarr/sdk": "*" }
}

Server entries are TypeScript, loaded at startup by tsx, so there's no build step. Web entries are bundled into the UI at build time.

Installing plugins

  • Server-only plugins: drop the folder into any directory listed in INKARR_PLUGIN_DIRS (colon-separated) and restart. In Docker, mount it, e.g. -v ./my-plugins:/plugins -e INKARR_PLUGIN_DIRS=/plugins.
  • Plugins with UI: place them in plugins/ of the repository and rebuild the image (docker build -t my-inkarr .). The UI only bundles what's present at build time.
  • Enable or disable any plugin under System → Plugins. The change takes effect after a restart.

If a plugin has dependencies of its own, run npm install inside its folder, or add it to the workspace.

Providers and settings fields

Indexers, download clients and connections are providers. A provider is a type that users can add several instances of, each with its own settings. You describe the settings, and Inkarr renders the form, stores the values, masks passwords and adds a Test button.

ctx.registerConnection({
  type: 'kavita',                    // unique id for this provider type
  name: 'Kavita',
  description: 'Scan a Kavita library after imports.',
  docsUrl: 'https://wiki.kavitareader.com',
  fields: [
    { key: 'url', label: 'URL', type: 'url', required: true },
    { key: 'apiKey', label: 'API key', type: 'password', required: true },
    { key: 'libraryId', label: 'Library ID', type: 'number', advanced: true },
  ],
  create: (settings, { log, dataDir }) => new Kavita(settings, log),
});

Common field options: required, default, help, placeholder, and advanced (hidden behind “Show advanced”). create() runs again whenever the settings change. Instances are cached, so keeping sessions or cookies on the instance is fine.

Indexer

interface Indexer {
  protocol: 'torrent' | 'ddl';
  mediaTypes: ('ebook' | 'audiobook')[];
  test(): Promise<{ ok: boolean; message?: string }>;
  search(q: { term: string; mediaType; book?: BookRef }): Promise<Release[]>;
  recent?(): Promise<Release[]>;       // enables RSS sync
}

interface Release {
  guid: string;          // stable per indexer
  title: string;         // used for matching: include author + title + format if you can
  protocol: 'torrent' | 'ddl';
  downloadUrl: string;   // magnet / .torrent URL / direct or hoster URL
  infoUrl?: string; size?: number; seeders?: number; leechers?: number;
  publishDate?: string; format?: string; language?: string;
  mediaType?: 'ebook' | 'audiobook';
}

Return everything you find. Inkarr scores, filters and de-duplicates the results. Setting format and mediaType when you know them improves matching a lot.

Download client

interface DownloadClient {
  protocols: ('torrent' | 'ddl')[];
  test(): Promise<TestResult>;
  add(release: Release, opts: { tag: string; mediaType }): Promise<string>;   // returns an id
  getItems(ids: string[]): Promise<DownloadItem[]>;
  remove?(id: string, deleteData: boolean): Promise<void>;
}

interface DownloadItem {
  id: string; name: string;
  status: 'queued' | 'downloading' | 'paused' | 'completed' | 'failed' | 'warning';
  progress: number;      // 0..1
  size?: number; eta?: number; message?: string;
  outputPath?: string;   // LOCAL path of the finished file/folder (apply mapRemotePath)
}

The tag (e.g. inkarr-42) is unique per grab. The simplest pattern is to label the download with it and return the tag as the id. Report completed only when the files are final; Inkarr imports right away.

Connection

interface Connection {
  test(): Promise<TestResult>;
  onGrab?(e: { book: BookRef; release: Release }): Promise<void>;
  onImport?(e: { book: BookRef; folder: string; files: string[] }): Promise<void>;
}

UI plugins

A web plugin default-exports defineWebPlugin() from web/index.tsx. It can add routes, sidebar entries (top-level, or under an existing section such as settings, system or activity), and panels on the book page.

import { Sparkles } from 'lucide-react';
import { defineWebPlugin, PageContent, PageToolbar, ToolbarButton, useApi } from '@inkarr/web-sdk';

function StatsPage() {
  const books = useApi<any[]>('/books');
  return (
    <>
      <PageToolbar><ToolbarButton icon={Sparkles} label="Refresh" onClick={() => books.refetch()} /></PageToolbar>
      <PageContent>You own {books.data?.length ?? '…'} books.</PageContent>
    </>
  );
}

export default defineWebPlugin({
  id: 'stats',
  routes: [{ path: '/stats', element: <StatsPage /> }],
  nav: [
    { id: 'stats', label: 'Stats', path: '/stats', icon: Sparkles, order: 50 },
    // or as a sub-entry: { id: 'stats', parent: 'system', label: 'Stats', path: '/stats' }
  ],
  bookPanels: [
    { id: 'notes', title: 'My notes', component: ({ book }) => <p>Notes for {book.title}</p> },
  ],
});

The core pages (Library, Activity, Settings, …) are themselves the core-ui plugin. Read plugins/core-ui/web/ for complete examples.

Full-stack example

Server and UI parts of one plugin communicate through plugin routes:

// server/index.ts
ctx.registerRoutes((app) => {
  app.get('/hello', (c) => c.json({ message: 'hi' }));   // GET /api/plugins/my-plugin/hello
});

// web/index.tsx
const hello = useApi<{ message: string }>('/plugins/my-plugin/hello');

Guidelines

  • Use timeouts on every network call (AbortSignal.timeout(…)). A hanging plugin delays searches.
  • Throw an Error with a helpful message. It's shown to the user next to the indexer or download.
  • Don't keep secrets anywhere other than password fields or ctx.store.
  • Respect site terms and rate limits, and only integrate sources users have the right to access.
