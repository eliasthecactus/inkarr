Books and media types

A book in your library is a work from a metadata source (Open Library by default) wanted in one media type: ebook or audiobook. To get both, Inkarr creates two library entries for the same work. Each has its own status, files and history, so an audiobook that's missing never blocks the ebook you already have.

StatusMeaningColour
MissingMonitored, nothing downloaded yet. Searched automatically.red
DownloadingA release was grabbed and is in the queue.blue
DownloadedFiles were imported into your library.green
UnmonitoredKept in the library, but never searched automatically.grey

Protocols

Every release has a protocol:

  • torrent: a magnet link or .torrent URL. Handled by torrent clients such as qBittorrent.
  • ddl: a direct download link, or a link to a file hoster. Handled by the built-in Direct Download client or by JDownloader.

Indexers declare which protocol they return. Download clients declare which protocols they accept. When a release is grabbed, Inkarr picks the enabled client with the best (lowest) priority that accepts its protocol. If none exists, the grab fails with a clear error and automatic search skips that release.

Searching and scoring

Searches go to every enabled indexer that supports the book's media type, in parallel. Each result is then scored and checked against rejection rules:

CheckEffect
Title words found in the release name (subtitle ignored)Fewer than 80% → rejected. Adds up to 100 points.
Author's last name found+50 points. Required when the title is only one or two words.
Media type detected (format, “unabridged”, “narrated”…)Rejected if it contradicts what you want.
Format (epub, m4b…)Rejected if not in your allowed list. Earlier formats in the list score higher.
Seeders (torrents)Fewer than the minimum → rejected. More seeders add up to 60 points.
Declared languageRejected if it differs from your configured language.

Automatic search grabs the highest-scoring release with no rejections. Interactive search on the book page lists every release, including the rejected ones. Hover the warning icon to see why a release was rejected, and grab any of them manually.

RSS sync

Every RSS sync interval minutes (15 by default), Inkarr fetches the newest releases from each indexer with Enable RSS turned on. It checks them against all missing, monitored books. This is how you pick up a new release without hammering indexers with searches.

Queue and import

Every 15 seconds Inkarr asks each download client about the items it added. Items are tagged inkarr-<id>, so Inkarr never touches your other downloads. When an item completes:

  1. The download path is translated with the client's remote path mapping.
  2. Files matching your allowed formats are collected. If there are none but there are .zip archives, they are extracted first.
  3. Ebooks: one file per format, renamed to {Author} - {Title}.{ext}.
    Audiobooks: all audio files keep their track structure, plus cover images and .cue files.
  4. Files are hardlinked, copied or moved into <root>/{Author}/{Title} ({Year})/. Torrents are never moved, so they keep seeding.
  5. The book becomes Downloaded and connections run onImport.

If an import fails (wrong path, no matching files), the queue item shows a warning with the reason, and the files stay where they are.

Plugins

The core holds the library, the queue, scoring, importing and the scheduler. Everything that talks to the outside world is a plugin, and so is every page of the UI. See Plugin development.
