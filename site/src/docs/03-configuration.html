Naming tokens

TokenExample
{Author}Mary Shelley
{Title}Frankenstein (subtitle removed)
{FullTitle}Frankenstein: Or, The Modern Prometheus
{Year}1818
{Series} / {SeriesIndex}Discworld / 01
{Format}epub (file names only)

Empty tokens are removed together with empty brackets, so {Title} ({Year}) becomes Title when there is no year. Characters that are invalid in file names are stripped.

Audiobookshelf tip: ABS expects Author/Title/ or Author/Series/01 - Title/. The default folder format works out of the box. For series, use {Author}/{Series}/{SeriesIndex} - {Title}.

Metadata sources

Settings → General → Metadata sources lists every installed metadata plugin and its settings.

SourceNotes
Open LibraryFree, no key. Good for English and classics. Some non-English records have damaged titles (e.g. “Die Hu tte”) or are missing; search by ISBN, or fix the title in the Add dialog.
Google BooksBetter coverage of German and other non-English editions. Needs a free API key: Google Cloud console → APIs & Services → enable “Books API” → Credentials → Create API key. Prefer language (e.g. de) restricts title searches to that language.

Title, author and year can be corrected when adding a book, or later with Edit on the book page. They are used for release matching and file naming.

Remote path mapping

When the download client runs in another container or on another machine, it reports paths that Inkarr can't see. Every download client plugin has two advanced fields:

  • Remote path: the path as the client reports it, e.g. /downloads.
  • Local path: the same folder as Inkarr sees it, e.g. /data/torrents.

The simplest fix is to mount the same host folder at the same path in every container. Then no mapping is needed.

Provider priority

Indexers, download clients and connections have a Priority (advanced, 1–50, default 25). Lower numbers win. With two torrent clients, releases go to the one with the lower number.

Security

Inkarr has no login screen yet. Run it on a trusted network or behind a reverse proxy with authentication (Authelia, Authentik, basic auth…). Setting INKARR_API_KEY requires an X-Api-Key header on every API request. In the UI, enter the key under Settings → General → This browser.

Passwords and API keys in provider settings are stored in the SQLite database and are never sent back to the browser in full; they appear as ********.

Backup

Everything lives in /config/inkarr.db, an SQLite database in WAL mode. Stop the container, or use sqlite3 inkarr.db ".backup backup.db", and copy the file.
