Repository layout

inkarr/
├── packages/
│   ├── sdk/            @inkarr/sdk      — server plugin contract (types + helpers)
│   └── web-sdk/        @inkarr/web-sdk  — UI plugin contract, API hooks, components
├── apps/
│   ├── server/         Hono API, SQLite (Drizzle), plugin loader, scheduler, importer
│   └── web/            React + Vite shell: header, sidebar, router; pages come from plugins
├── plugins/            one folder per plugin (server/, web/ or both)
├── site/               this documentation + landing page (GitHub Pages)
├── Dockerfile          multi-stage image published to ghcr.io
└── .github/workflows   ci.yml, release.yml (GHCR), pages.yml (docs)

Local development

npm install
npm run dev            # server (tsx watch, :8585) + Vite UI (:5173, proxies /api)
npm run typecheck
node --import tsx --test apps/server/test/*.test.ts
node site/build.mjs    # docs → site/dist

Data goes to ./data unless INKARR_DATA is set.

Core modules

FileResponsibility
plugins.tsDiscovers plugin folders, imports server entries, builds the PluginContext.
providers.tsStores provider instances, instantiates and caches them, adds core fields.
parser.tsRelease parsing, scoring and rejection rules (unit-tested).
library.tsSearch, grab and auto-search orchestration.
core-tasks.tsQueue refresh, RSS sync, search-wanted, and the scheduler.
importer.tsFile selection, archive extraction, naming, hardlink/copy/move.
api.tsREST endpoints, including plugin route mounting.

Releasing

  1. Bump the version in package.json.
  2. Tag it: git tag v0.2.0 && git push --tags.
  3. release.yml builds linux/amd64 + linux/arm64 and pushes ghcr.io/eliasthecactus/inkarr:0.2.0, :0.2 and :latest. Every push to main updates :develop.

The first time, make the package public under GitHub → Packages → inkarr → Package settings. For the docs, enable Settings → Pages → Source: GitHub Actions.
