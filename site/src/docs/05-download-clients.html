How it works

  • Magnet links go straight to qBittorrent. For .torrent URLs, Inkarr downloads the file itself and uploads it. Indexer links often only work from Inkarr's network, and some redirect to a magnet link; both cases are handled.
  • Every torrent gets the tags inkarr and inkarr-<id>. Inkarr only looks at torrents with its own tags.
  • A torrent counts as complete as soon as it reaches 100% (seeding states). Imports use hardlinks, so seeding continues.
  • Removing an item from the queue can also remove it from qBittorrent, with or without its data.

Direct Download (built-in)

A small HTTP downloader inside Inkarr for releases with protocol ddl that point at a file, such as Gutenberg, LibriVox or your own server.

If a link returns an HTML page instead of a file (a hoster's landing page, a captcha), the download fails with a hint to use JDownloader. Running downloads live in memory: after a restart, unfinished items are marked failed and the book becomes wanted again.

JDownloader 2

For file hosters with wait times, captchas or premium accounts, Inkarr passes the link to JDownloader through its local API.

Enable the local API

  1. In JDownloader, open Settings → Advanced Settings.
  2. Search for DeprecatedApi and set RemoteAPI: Deprecated Api Enabled to true.
  3. Restart JDownloader. The API listens on port 3128. Don't expose it beyond your network.

Links are added with autostart, and each package is named inkarr-<id> <release title>. While a package sits in the LinkGrabber (link check, captcha), the queue shows it as queued.

The JDownloader plugin uses JD's local API, which JD labels “deprecated” but still ships. Support for the My.JDownloader cloud API would make a good community plugin.

Which client gets a release?

The enabled client with the lowest priority number that supports the release's protocol. To prefer JDownloader over the built-in downloader for DDL, give JD a lower priority number.
