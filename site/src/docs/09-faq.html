“Import failed: download path not found”

The download client reported a path Inkarr can't see. Either mount the downloads folder at the same path in both containers, or set Remote path and Local path on the download client (details). The queue message shows the exact path Inkarr tried.

“No ebook files found in download”

The download finished but contains none of your allowed formats. Maybe it only has a .rar, or a format you excluded. Check Settings → Formats & Rules. Zip archives are extracted automatically; RAR is not supported yet.

Search finds nothing

  • Check that at least one indexer supports the book's media type (Use for on Torznab).
  • Open the book and use Interactive search. Indexer errors are listed above the results.
  • Very long titles: Inkarr searches author + main title without the subtitle, but some indexers need fewer words.

Everything is rejected

Hover the ⚠ icon in interactive search to see the reasons. The usual causes are a title mismatch (a translated title, or the release uses a series name) or a format that isn't in your list. You can always grab a rejected release manually.

Files are copied instead of hardlinked

Hardlinks only work within one filesystem and one Docker mount. Mount a common parent (e.g. /data) instead of separate /downloads and /books volumes.

Will you add site X?

Inkarr doesn't include scrapers for sites whose main purpose is distributing copyrighted books without permission. For torrent trackers, use Torznab through Prowlarr or Jackett, which manage indexer definitions. Anything else can be a plugin. See Plugin development.

How is this different from Readarr?

Readarr was retired in 2025. Inkarr is a fresh codebase with no shared code. It's written in TypeScript and built around a plugin system, so every integration can be replaced. It also treats ebook and audiobook as two wants of the same work, and supports direct downloads as well as torrents.

Where are the logs?

System → Logs shows the last 1000 entries, and the container's stdout has everything (docker logs inkarr). Set INKARR_DEBUG=1 for more detail.

How do I start over?

Stop Inkarr and delete /config/inkarr.db*. Your media files are never deleted by Inkarr.
